# 开发难点与设计演进

这份文档记录 Agentic RAG 平台从简单问答 demo 向可扩展工程骨架演进时的关键取舍。

## 1. 从聊天 demo 转向工程平台

如果只做“上传文档然后聊天”，系统很难解释召回错误、工具失败、状态丢失和用户取消等真实问题。因此当前实现把链路拆成 `understand`、`retrieve`、`rerank`、`tool`、`answer` 多个节点，每一步都有状态字段和事件输出。

这种拆分带来的收益是：

- 问答质量问题可以按节点定位；
- 前端能实时展示执行过程；
- 后端可以沉淀 trace 和评测数据；
- 后续迁移 LangGraph、向量库、reranker 时边界清晰。

## 2. 记忆不应该全部向量化

把所有历史对话写入向量库会带来检索变慢、冲突记忆难删除、过期事实污染回答等问题。项目采用分层记忆思路：

- Redis 保存短期会话、最近消息、限流和 checkpoint 指针；
- 向量库只保存长期语义知识；
- trace 和工具日志单独保存；
- 反思经验可以沉淀到独立经验库。

这样既保留多轮上下文，又避免把任务状态、用户偏好和长期知识混在一起。

## 3. RAG 排查不能只改 prompt

RAG 答非所问时，优先排查数据和召回链路：

1. 文档清洗是否破坏标题、表格和编号结构；
2. chunk 是否过大或过小；
3. overlap 是否覆盖关键上下文；
4. embedding 是否适合中文和业务语料；
5. metadata filter 是否误过滤；
6. top_k 是否合理；
7. 是否需要 BM25、SQL 或图谱多路召回；
8. reranker 是否把关键证据排到前面；
9. prompt 是否要求基于证据回答并在证据不足时拒答。

项目保留 Evidence API，后续替换召回组件时不影响上层 workflow。

## 4. SSE 是交互层也是观测层

Agent 调用链比较长，如果用户只看到最终答案，很难判断系统卡在哪里。SSE 事件可以持续输出：

- 当前执行到哪个节点；
- 召回了多少证据；
- 调用了哪个工具；
- 工具是否失败；
- 最终引用了哪些证据。

同一套事件也能进入日志、trace 和评测系统，支撑线上调试与质量分析。

## 5. 工具 schema 必须结合业务校验

Function Calling 或 MCP 只能保证参数结构接近 schema，不能保证业务合法。例如：

- 参数类型合法，但订单不属于当前用户；
- 工具可以调用，但当前意图不允许；
- 查询结果来自旧缓存；
- 工具返回内容被提示注入污染。

所以项目在工具 registry 中保留 `allowed_intents`、结构化错误码和业务校验入口。生产版还需要补充租户隔离、权限、幂等、超时和审计日志。

## 6. 为什么先做轻量实现

当前仓库采用轻量实现，是为了先把工程边界和可替换接口做清楚：

- API 边界清楚；
- 状态字段清楚；
- 事件流清楚；
- 扩展路径清楚；
- 文档能解释真实开发问题。

后续可以逐步把 keyword retriever 替换成 Milvus / pgvector，把 workflow 替换成 LangGraph，把 memory 换成 Redis Cluster 或 Postgres checkpoint。

## 7. 从展示骨架升级到可评测平台

本轮增强把项目从“能跑的 RAG 骨架”推进到“可演示、可评测、可排障”的平台形态：

- 增加文档列表和检索诊断 API，让知识库规模、BM25 排名、向量排名和 RRF 融合结果可见；
- 增加 `quality` 节点，在证据不足时拒答，而不是把弱证据交给模型硬生成；
- 增加离线 retrieval eval，输出 Hit@K、MRR 和 failed cases；
- 增加可选 OpenAI-compatible LLM 客户端，默认模板 fallback，接 vLLM/Qwen 时只需环境变量；
- 增加演示知识库和脚本，覆盖 RAG 幻觉、Agent Harness、工单故障、向量库慢查询等真实应用问题；
- 前端增加文档管理、检索诊断和评测展示区。

这个演进的核心不是把项目做大，而是把面试官会追问的问题落实到代码路径：

```text
召回不准怎么定位 -> /api/retrieve
有没有评测指标 -> scripts/run_rag_eval.py
证据不足怎么办 -> quality gate
如何接本地大模型 -> app/llm/client.py
工具调用怎么控权 -> ToolRegistry schema + allowed_intents
执行过程怎么看 -> SSE + task trace
```
